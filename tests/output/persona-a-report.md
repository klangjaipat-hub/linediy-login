## Think Aloud Protocol (ภาษาไทย)

### Step 1 — Login with LINE → Locked Mode Dashboard

> *"โอ้ หน้าแรกมีให้เลือก New User กับ Existing User... เราเป็นคนใหม่ก็เลือก New User ก่อนเลย แล้วกด Login with LINE ตามปกติ ไม่ยากเลย"*

> *"หน้า Dashboard โหลดมาแล้ว... มีเมนูด้านซ้ายหลายอัน แต่เห็นว่ามีกุญแจล็อกอยู่หลายเมนูเลย เหมือนว่าเข้าไม่ได้ แถบสีเหลืองบอกว่า 'ปลดล็อกประสบการณ์เต็มรูปแบบ' อ๋อ คือยังใช้ได้ไม่ครบ... แต่ตอนนี้ขอดูก่อนว่ามีอะไรบ้าง"*

**การสังเกต:** ผู้ใช้ใหม่เข้าใจ flow Login ได้ทันที และสังเกตเห็น Locked state ของ Dashboard แต่ยังไม่เข้าใจนัยยะของ "Basic ID" จากการมองแค่ Banner

---

### Step 2 — เห็น Broadcast card → คลิก "สั่งซื้อ"

> *"เห็น 4 กล่องบริการ... Broadcast อยู่กล่องแรก เป็นอะไรเกี่ยวกับการส่งข้อความ ดูน่าสนใจ กด 'สั่งซื้อ' เลย"*

> *"ไม่มีอะไรขัดขวาง กดได้เลย ดีกว่าที่คิด เพราะเมนูด้านซ้ายยังล็อกอยู่เลย นึกว่าปุ่มนี้จะล็อกด้วย"*

**การสังเกต:** ปุ่ม "สั่งซื้อ" บน Service Card ใช้งานได้ปกติแม้อยู่ใน Locked Mode ผู้ใช้ไม่ถูก Block ที่จุดนี้ — เป็นการตัดสินใจ UX ที่ถูกต้อง แต่ผู้ใช้เกิดความสับสันเล็กน้อยว่า "อะไรล็อก อะไรไม่ล็อก" เนื่องจากยังไม่มีการอธิบายความแตกต่าง

---

### Step 3 — พบฟอร์ม Validation "ซื้อบริการ — BROADCAST PACKAGE"

> *"หน้าต่อมาเป็น Form ชื่อ 'ซื้อบริการ — BROADCAST PACKAGE' โอเค... มีส่วน Account ให้เลือก แล้วก็มีแผนราคา"*

> *"เห็นคำว่า 'Basic ID' อีกแล้ว ตรงนี้มีไอคอน ⓘ ให้กด ลองกดดู... โอ้ บอกว่า 'Basic ID คือรหัส @username ของ LINE OA เช่น @myshop' อ๋อ คือชื่อ account LINE OA นั่นเอง ตอนแรกนึกว่าเป็นอะไรเทคนิคมาก"*

> *"มี Radio Button สองตัว 'เปิดบัญชีใหม่' กับ 'ระบุ Basic ID เดิม' เราเป็นคนใหม่เลยเลือก 'เปิดบัญชีใหม่' ซึ่งเลือกอยู่แล้วด้วย ดี"*

**การสังเกต:** Tooltip ⓘ บน "Basic ID" ช่วยได้มาก ผู้ใช้ใหม่ที่ไม่รู้จัก Term นี้สามารถเข้าใจได้ด้วยตัวเองโดยไม่ต้องออกจาก Flow — นี่คือ improvement ที่ชัดเจนจาก v2

---

### Step 4 — เลือก "เปิดบัญชีใหม่"

> *"'เปิดบัญชีใหม่' ถูก Default ไว้แล้ว เราก็ไม่ต้องทำอะไรเพิ่ม แค่ดูว่า Field ที่ต้องกรอกมีอะไรบ้าง"*

> *"มี Field 'ชื่อแสดงผล (Display Name)' มีดาวแดง หมายความว่าต้องกรอก โอเค ไม่ยาก แล้วก็เลือก Plan ด้วย มี Basic ฿1,500 กับ Pro ฿3,000"*

> *"แต่ตอนนี้ยังไม่แน่ใจว่า Plan ต่างกันยังไง ไม่เห็นรายละเอียดเพิ่มเติม... ลองคิดว่าเลือก Basic ก่อนก็ได้ ดูเหมือน default อยู่แล้ว"*

**การสังเกต:** ผู้ใช้ยอมรับ Default option โดยไม่ได้อ่าน Plan comparison ลึกซึ้ง เป็นพฤติกรรมปกติของ Beginner — การที่ไม่มี Plan comparison detail ที่ชัดเจนอาจทำให้ผู้ใช้รู้สึก under-informed แต่ไม่ได้ Block Task Completion

---

### Step 5 — กรอก Display Name → คลิก "ยืนยันคำสั่งซื้อ"

> *"พิมพ์ชื่อร้านลงใน 'ชื่อแสดงผล' เสร็จแล้ว... ปุ่ม 'ยืนยันคำสั่งซื้อ' ยังเป็นสีเทาอยู่ รอดูว่า..."*

> *"โอ้ พอกรอกแล้วปุ่มกลายเป็นสีเขียว กดได้แล้ว! กดเลย"*

**การสังเกต:** Disabled → Enabled state transition ทำงานได้ถูกต้องและผู้ใช้ตีความได้ทันที ไม่มีความสับสน ถือว่า Affordance ชัดเจน

## UX Report

### Metric 1 — Task Success Rate

| | v2 | v3 | Delta |
|---|---|---|---|
| Target | >80% | >80% | — |
| Estimated Rate | 75% | **92%** | +17pp |

**คะแนน: ผ่าน (เกิน Target)**

**วิเคราะห์:**
v3 ทำ Task Success Rate ดีขึ้นอย่างมีนัยสำคัญ เหตุผลหลักมาจาก 2 การเปลี่ยนแปลง:

1. **Tooltip ⓘ บน Basic ID** ทำให้ผู้ใช้ใหม่ไม่ติด Barrier ที่คำศัพท์เทคนิค ใน v2 ผู้ใช้จำนวนไม่น้อยหยุดที่ Form เพราะไม่รู้ว่า "Basic ID คืออะไร" และไม่แน่ใจว่าควรเลือก Option ใด
2. **Blocking Modal สำหรับ Locked Menus** ไม่ได้เพิ่ม Friction ในเส้นทาง Happy Path (Broadcast Card → Form) แต่ช่วยป้องกัน Dead-end สำหรับผู้ใช้ที่อาจคลิกเมนูล็อกก่อน — เพราะได้รับ Feedback ชัดเจนและมีทางออกที่ถูกต้อง

**ข้อควรระวัง:** ยังมี ~8% ที่อาจไม่สำเร็จ สาเหตุที่น่าจะเกิดได้คือผู้ใช้ไม่เข้าใจ Plan difference และออกจาก Flow ก่อนตัดสินใจ

### Metric 2 — Time on Task / Friction

| | v2 | v3 | Delta |
|---|---|---|---|
| Target | 30–45s | 30–45s | — |
| Estimated Time | ~50–65s | **~35–45s** | -15–20s |

**คะแนน: ผ่าน (อยู่ใน Target)**

**วิเคราะห์:**
เวลาลดลงอย่างชัดเจน เหตุผลหลัก:

- **Tooltip แก้ปัญหา "Basic ID Confusion" ได้ใน 3–5 วินาที** แทนที่จะต้อง Drop off ไปหาข้อมูลภายนอกหรือลังเลนานกว่านั้น
- **Radio "เปิดบัญชีใหม่" เป็น Default** ลดการตัดสินใจ 1 ขั้น
- **Disabled State ที่ชัดเจนบนปุ่ม ยืนยันคำสั่งซื้อ** ทำให้ผู้ใช้ไม่เสีย Cycle พยายามกดปุ่มที่ยังใช้ไม่ได้

**จุดยังมี Friction:**
- ผู้ใช้ยังต้องอ่าน Plan (Basic vs Pro) และตัดสินใจโดยไม่มี comparison detail — อาจเพิ่มเวลาในกลุ่ม "คิดมาก" ประมาณ +5–10 วินาที
- Label "ชื่อแสดงผล (Display Name)" อาจทำให้บางคนไม่แน่ใจว่าควรพิมพ์ชื่อร้านหรือชื่อตัวเอง

## Recommendations สำหรับ v4

**P1 — ต้องแก้ก่อน:**
1. **Plan Comparison Detail:** เพิ่ม Feature bullet list ใต้ Basic / Pro card เพื่อให้ผู้ใช้ตัดสินใจได้อย่างมีข้อมูล ลด Post-purchase Regret
2. **Label "ชื่อแสดงผล":** เพิ่ม Placeholder hint เช่น "เช่น ร้านกาแฟของฉัน" เพื่อลดความลังเลว่าควรพิมพ์อะไร

**P2 — ควรแก้:**
3. **Locked vs Unlocked Visual Boundary บน Dashboard:** เพิ่ม Section label หรือ Visual separator ที่ชัดขึ้นว่า Service Cards ใช้ได้ทันทีแม้ยังไม่มี Basic ID เพื่อลด Mental Load ของผู้ใช้

**P3 — Nice-to-have:**
4. **Progress Indicator บน Form:** ผู้ใช้ที่ไม่รู้ว่า Flow ยาวแค่ไหนอาจรู้สึกไม่แน่ใจ — Step indicator เล็กๆ เช่น "1/2" จะช่วยได้
5. **Tooltip บน Plan Names:** ใส่ Tooltip สั้นๆ บน "Basic" และ "Pro" เพื่อสรุป Use case หลักในประโยคเดียว
